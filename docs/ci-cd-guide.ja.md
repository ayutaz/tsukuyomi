# CI/CD ワークフローガイド

Tsukuyomi TTSプロジェクトでは、GitHub Actionsを使用した包括的なCI/CDパイプラインを構築しています。

## ワークフロー概要

### 1. 統合CI管理 (ci.yml)
メインのCI/CDオーケストレーターとして機能し、条件に応じて適切なワークフローを呼び出します。

- **トリガー条件**: すべてのプッシュ、プルリクエスト、手動実行
- **動作**:
  - PR、mainブランチ、手動実行 → 包括的品質検証を実行
  - その他のブランチ → 高速品質チェックを実行

### 2. 高速品質チェック (quick-check.yml)
開発中の迅速なフィードバックを提供する軽量チェック。

- **トリガー条件**: dev, feat/*, fix/* ブランチへのプッシュ
- **実行内容**:
  - コード品質チェック（Black、isort、Ruff、mypy）
  - 基本動作テスト（インポート確認、基本的なユニットテスト）
  - ファイル検証・セキュリティスキャン（大容量ファイル、TODO/FIXME、Bandit）

### 3. 包括的品質検証 (full-ci.yml)
本番環境へのデプロイ前の完全な品質保証。

- **トリガー条件**: mainブランチ、プルリクエスト、リリースタグ
- **実行内容**:
  - マルチプラットフォームテスト（Ubuntu、Windows、macOS × Python 3.11、3.12）
  - GPU加速テスト・パフォーマンスベンチマーク
  - セキュリティ脆弱性診断（Trivy、Bandit）
  - パッケージビルド・検証
  - Dockerイメージビルド

### 4. リリース・デプロイ管理 (deploy.yml)
自動リリースとパッケージ配布を管理。

- **トリガー条件**: バージョンタグ（v*）のプッシュ、手動実行
- **実行内容**:
  - リリースバージョン検証
  - リリースアーティファクト作成
  - GitHubリリース作成（自動リリースノート生成）
  - PyPIパッケージ公開
  - Dockerイメージビルド・公開（Docker Hub、GitHub Container Registry）

## ブランチ戦略

- **main**: 本番環境相当、包括的品質検証を実行
- **dev**: 開発ブランチ、高速品質チェックを実行
- **feat/*, fix/**, bug/**など: 機能開発ブランチ、高速品質チェックを実行

## セキュリティ対策

1. **Bandit**: Pythonコードの静的セキュリティ分析
2. **Trivy**: Dockerイメージと依存関係の脆弱性スキャン
3. **Safety**: Pythonパッケージの既知の脆弱性チェック
4. **pre-commit hooks**: ローカル開発時のセキュリティチェック

## 最適化機能

- **並行実行制御**: 同一ブランチの重複実行を自動キャンセル
- **依存関係キャッシング**: pip、apt、Dockerレイヤーのキャッシュ
- **条件付き実行**: 変更内容に応じた必要なテストのみ実行
- **マトリクステスト**: 複数環境での並列テスト実行

## 使用方法

### 手動実行
```bash
# GitHub CLIを使用
gh workflow run "統合CI管理"
```

### ローカルでの事前チェック
```bash
# pre-commitフックの設定
pre-commit install

# 手動でのチェック実行
make lint
make test-fast
```

## トラブルシューティング

### テスト失敗時
1. ワークフローの詳細ログを確認
2. ローカルで同じテストを実行して再現
3. `make test-fast` で基本的なテストを実行

### ビルド失敗時
1. 依存関係の確認（requirements.txt、pyproject.toml）
2. Pythonバージョンの確認（3.11以上）
3. プラットフォーム固有の問題を確認
