XPhoneBERTの導入と音素変換
XPhoneBERTモデルとトークナイザの読み込み: Hugging Faceの事前学習済みモデルvinai/xphonebert-baseを利用します。transformersからAutoModelおよびAutoTokenizerを使用してモデル本体とトークナイザをロードします
github.com
。さらに、XPhoneBERT用に提供されているText2PhonemeSequenceクラスを用いてテキストを音素列に変換します
github.com
。
import torch
from transformers import AutoModel, AutoTokenizer
from text2phonemesequence import Text2PhonemeSequence

# XPhoneBERTモデルとトークナイザのロード
xphonebert = AutoModel.from_pretrained("vinai/xphonebert-base")
tokenizer = AutoTokenizer.from_pretrained("vinai/xphonebert-base")
対応言語の音素エンコーダ設定: Text2PhonemeSequenceを使用して、各言語それぞれに対応する音素変換器を準備します。Text2PhonemeSequenceのlanguage引数にはISO 639-3コードを指定します
github.com
。例えば、日本語は 'jpn'、英語（米国）は 'eng-us'、中国語（北京官話）は 'cmn' を指定します。
# 各言語用の音素変換器を初期化（CUDA対応の場合 is_cuda=True）
phonemizer_ja = Text2PhonemeSequence(language='jpn', is_cuda=True)      # 日本語
phonemizer_en = Text2PhonemeSequence(language='eng-us', is_cuda=True)   # 英語（米語）
phonemizer_zh = Text2PhonemeSequence(language='cmn', is_cuda=True)      # 中国語（官話）
注意: CJK言語（中日韓など）では文章中に空白で区切られた単語境界がありません。そのため、Text2PhonemeSequenceに渡す前に単語分かち書きを行う必要があります
github.com
github.com
。例えば日本語では形態素解析（MeCabやspaCyのjaモデル等）、中国語ではjieba等で単語ごとに空白を挿入してください。英語についても、必要に応じて正規化（例: 全て小文字にする、数字を単語に展開する等）を行ってから音素変換すると良いでしょう
github.com
。
テキストから音素列への変換: サンプルテキストを各言語で用意し、上記のphonemizerで音素列に変換します。入力文字列は単語単位で空白区切りされた状態で渡します
github.com
github.com
。例えば:
日本語: "これはテストテキストです。" → "これ は 、 テスト テキスト です ."（単語毎・記号毎に空白を挿入）
英語: "This is a test." → "this is a test ."（必要ならば前処理で小文字化と句読点前後に空白）
中国語: "这是一个测试。" → "这 是 一个 测试 ."（簡易には各漢字・単語の間に空白を入れる）
変換コード例（日本語のケース）:
sentence_ja = "これ は 、 テスト テキスト です ."  # すでに分かち書き・正規化済みの文字列
phoneme_seq = phonemizer_ja.infer_sentence(sentence_ja)
print(phoneme_seq)  
# 例: phoneme_seq が "k o r e w a , t e s u t o t e k i s u t o d e s u ." のような音素系列になる
上記のphoneme_seqには、スペースで区切られた音素記号列が文字列として得られます。次に、この音素列をXPhoneBERTのトークナイザでID列に変換します
github.com
。
inputs = tokenizer(phoneme_seq, return_tensors="pt")
音素ベクトル埋め込みの取得: 準備したinputsをXPhoneBERTモデルに入力し、隠れ状態特徴量を取得します
github.com
。通常、AutoModelでロードしたモデルの出力featuresにはlast_hidden_state（最終層の隠れベクトル列）が含まれます。これが各音素に対応した多言語音素埋め込みベクトルとなります。コード例:
with torch.no_grad():
    features = xphonebert(**inputs)
phoneme_embeddings = features.last_hidden_state  # サイズ: [バッチサイズ, 音素トークン数, 埋め込み次元]
ここで得られる phoneme_embeddings は、各音素トークン（系列長に相当）について768次元（BERT-baseと同じ次元）の埋め込みベクトルを含むテンソルです。このベクトル列を後段のVITSモデルに渡すことで、テキストエンコーダ部分を強化することが狙いです
github.com
github.com
。
メモ: この段階ではXPhoneBERTによる多言語対応の音素表現が得られました。後続のVITSモデルにこの表現を統合することで、少ない学習データでも音質やプロソディが向上する可能性が示されています
github.com
。
事前学習済みVITSモデルの選定と読み込み
適切なVITSモデルの選定: 次に、XPhoneBERTの出力と統合するTTSモデルとしてVITSアーキテクチャの事前学習モデルを用意します。多言語（日本語・英語・中国語）対応の単一モデルが理想ですが、公開されているものが無い場合は言語ごとのモデルを用意して切り替える方法もあります。代表的な選択肢:
Facebook MMS-TTSモデル: Meta社の「Massively Multilingual Speech」プロジェクトのTTSモデルです
huggingface.co
。1100以上の言語に対応し、各言語ごとにVITSベースの生成器モデルが公開されています
huggingface.co
。例: 英語モデルfacebook/mms-tts-eng、日本語モデルfacebook/mms-tts-jpnなど。中国語(普通話)についてはMMS-TTSでの公開はありません（2023年時点）
github.com
github.com
。
学術研究版マルチリンガルVITS: Edressonらの“YourTTS”
github.com
はVITSを拡張して英語・ポルトガル語・フランス語等で学習されたモデルです。ただし日本語・中国語は含まれていません。
各言語の単独モデル: 英語であればLJSpeechデータで学習した単一話者モデル、もしくはLibriTTSやVCTKで学習した多話者モデルが入手可能です
k2-fsa.github.io
。中国語はAISHELL-3多話者コーパスで学習したVITSモデル
k2-fsa.github.io
やBZNSYP単一話者モデル等が存在します。日本語はJSUTやJVSデータセットで学習されたVITSモデル（例: ESPnetによる日本語VITS
huggingface.co
など）が利用できます。例えば、Sherpaプロジェクトでは中国語+英語の2言語に対応したシングルスピーカーモデル「vits-melo-tts-zh_en」が公開されています
k2-fsa.github.io
。
初期検証としては、各言語で安定した発話が得られるモデルを別々に用意し、パイプラインの動作確認をする方法が確実です。ここでは例として:
日本語: 日本語単一話者のVITSモデル
英語: LJSpeechで訓練済みのVITSモデル
中国語: AISHELL-3ベースの多話者VITSモデル
を使用するものと仮定します（実際には手元にある事前学習モデルに置き換えてください）。
モデルの読み込み: VITSの実装および事前学習済み重みのロードには、モデルの提供元に応じた手順を踏みます。2通りのアプローチがあります。
(A) Hugging Face Transformers経由: 上記MMS-TTSのようにHugging Face Hubで提供されている場合、transformersのVitsForConditionalGeneration（またはAutoModel）でロード可能です。例えば英語モデルなら:
from transformers import VitsForConditionalGeneration, AutoTokenizer
vits_model_en = VitsForConditionalGeneration.from_pretrained("facebook/mms-tts-eng")
tokenizer_en = AutoTokenizer.from_pretrained("facebook/mms-tts-eng")
このようにモデルとトークナイザをロードし、テキストを入力すると音声波形を生成できます。注意: MMS-TTSの場合、モデル内部で自動的にテキスト→音素変換（phonemize）が行われる仕様があります
huggingface.co
。本ガイドではXPhoneBERTで音素に変換済みのため、トークナイザ側でphonemize機能をオフにする必要があります（VitsTokenizerのphonemize=False設定など）。
(B) オリジナル実装を使用: 学習元のGitHubレポジトリや独自チェックポイントがある場合、そのコードベースをクローンしてモデル構造を定義し、提供されたチェックポイントファイル（例: G_****.pth）をロードします
huggingface.co
。例えば公式VITS実装やCoqui TTSフレームワークを使う場合、対応するconfig.jsonを読み込みネットワークを構築し、重みをロードします。コード例（疑似コード）:
import torch
from VITS_impl import SynthesizerTrn  # VITSモデルクラス（実装に応じて異なる）
# 設定ファイルの読み込みとモデル初期化
config = load_config("config.json")
vits = SynthesizerTrn(**config["model"])  
# 重みロード
ckpt = torch.load("G_checkpoint.pth", map_location="cpu")
vits.load_state_dict(ckpt["generator"])
vits.eval().to(device)
その後、テキストを音素ID列に変換し（モデルに付属の辞書やphoneme setに合わせる必要があります）、モデルの推論関数を呼び出します。
XPhoneBERT出力との統合: ロードしたVITSモデルにXPhoneBERTの埋め込み出力を統合する方法はいくつか考えられます。
テキストエンコーダ層の置換: VITSのテキストエンコーダ部分（通常は音素IDをembeddingし畳み込みやTransformerで処理する部分）を省略し、代わりにXPhoneBERTから得たphoneme_embeddingsを直接モデルの残りに投入します
github.com
。具体的には、phoneme_embeddings（サイズ [1, T_phoneme, 768]）をVITS内部の埋め込み次元に射影する全結合層を新設し、その出力を本来のテキストエンコーダ出力に相当する箇所に接続します。
埋め込みの追加入力: VITSのテキストID埋め込みに対し、XPhoneBERTの埋め込みを加算あるいは連結する方法もあります。例えば、まず通常通り音素IDをVITSのembedding層でベクトル化し、それにXPhoneBERT埋め込みを加算してからVITSデコーダに送る、といった実装も可能です。
これらの変更を行う場合、既存モデルとの不整合（埋め込み次元の差異など）が生じるため、小規模でも良いので統合後のモデルを調整・ファインチューニングすることが望ましいです。初期検証の段階では、大きな学習は行わずとも、上記変更によってモデルが動作するかどうかを確認します。その際、音質が低下したり発話がおかしくなる可能性がありますが、これは統合時に追加したレイヤーが最適化されていないためです。あくまで「動く」ことの確認が目的であれば、ここでは細かいチューニングは後回しにします。
参考情報: XPhoneBERTの公式実装では、テキスト→音素列変換にtext2phonemesequenceを用い、その音素列をVITS2モデルに入力するデモが公開されています
github.com
。このように、まず音素ID列を取得してからXPhoneBERT組み込みのVITSで推論するという手順になります。
BigVGANボコーダーの導入と読み込み
BigVGANモデルの準備: BigVGANは高品質な汎用神経ボコーダで、入力のメルスペクトログラムから音声波形を生成します
huggingface.co
。NVIDIA提供の公式実装では、Hugging Face Hubに学習済みモデルが公開されており、そこで用意されたコードを使って簡単に推論が可能です
github.com
github.com
。例えば22.05kHzサンプリング・80次元メルスペクトログラム対応のモデルを使う場合、以下のように読み込みます（PyPI版をインストール済みの場合）
huggingface.co
huggingface.co
:
import bigvgan
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
# Hugging Face上のプリトレイン済みBigVGANボコーダをロード
vocoder = bigvgan.BigVGAN.from_pretrained("nvidia/bigvgan_22khz_80band", use_cuda_kernel=False)
vocoder.remove_weight_norm()  # 重み正規化を除去して推論を安定化
vocoder.eval().to(device)
上記では22kHz・80バンドメル用のモデルを選択しています
huggingface.co
。もしVITS側のメルスペクトログラムが24kHz・100バンドなど異なる次元の場合、対応するBigVGANモデル（例: "nvidia/bigvgan_24khz_100band" 等）を選んでください
huggingface.co
。BigVGANは大規模なデータで学習されており、複数言語の音声も含まれるため、どの言語のメルスペクトログラムに対しても高品質な波形再構成が期待できます
huggingface.co
。
テストデータでの推論パイプライン
入力テキストの準備: 日本語・英語・中国語それぞれで短いテスト文を用意します（前述のとおり、事前に単語分割・正規化を済ませてください）。例えば:
日本語: "これはテストです。"
英語: "This is a test."
中国語: "这是一个测试。"
これらをそれぞれのText2PhonemeSequenceで音素系列に変換します（ステップ5参照）。そしてXPhoneBERTのtokenizerでテンソル化し、XPhoneBERTモデルで埋め込み特徴を得ます（ステップ6参照）。
VITSによるメルスペクトログラム生成: 続いて、選定したVITSモデルを使って音声の中間表現であるメルスペクトログラムを生成します。ここでは各言語ごとに対応するVITSモデルを使う想定です。例えば日本語テキストには日本語VITSモデルを使用します。
XPhoneBERT統合なしで試す場合（まず通常のパイプライン検証）: 音素系列をそのままVITSモデルに与えて音声を合成します。Hugging Face経由のモデルであれば、テキストまたは音素列文字列をトークナイザでID化し、model.generate()やmodel(**inputs)で波形出力が得られます
huggingface.co
。公式実装の場合はvits.inference(text_ids, ...)のような専用関数でメルスペクトログラムや波形を計算します。例えばCoqui TTSのVITS実装では、model.inference(text, speaker_id, language_id)で直接波形生成まで可能です。ここでは最終出力波形ではなく中間のメルスペクトログラムが欲しいため、モデル内のデコーダ出力を取得する必要があります。
HuggingFace版VITSの場合、VitsForConditionalGenerationのgenerateメソッドは最終波形を返しますが、output_hidden_states=Trueなどのオプションで隠れ層（メルスペクトログラム相当）の出力を得られる可能性があります
huggingface.co
huggingface.co
。ドキュメントによれば、VITSモデルのhidden_statesにHiFi-GANに渡す前のスペクトログラムが含まれるとの記述があります
huggingface.co
。従って、outputs = model.generate(**inputs, output_hidden_states=True)とし、outputs.hidden_statesからスペクトログラムを取り出すことが考えられます。
独自実装の場合、VITSのデコーダ出力であるメルスペクトログラム（もしくはそれに類する表現）を直接取り出します。例えば公式実装のSynthesizerTrnでは、model(x, ... return_mel=True)のような引数設定でメル出力を得ることもできます。もしそのようなAPIが無ければ、モデルのコードを読むか、一度波形まで生成してしまいそこから改めてメルスペクトログラムを計算する方法もあります。
XPhoneBERT統合後の実行: XPhoneBERTのphoneme_embeddingsを統合する改造を施した場合は、そちらのモデルを使って推論します。手順は概ね同じですが、入力として音素ID列ではなく前段で得たphoneme_embeddingsを内部に渡す処理になっている点が異なります。適切に統合できていれば、あとは通常のVITS推論と同様にメルスペクトログラムが得られます。
いずれの場合も、**メルスペクトログラム（次元: [メルバンド数, フレーム数]）**が得られればOKです。例えば、得られたmelテンソルの形が(1, 80, T)（バッチ次元1、メルバンド80、フレーム長T）であることを確認します。
BigVGANによる波形再構成: 次に、ステップ12で得られたメルスペクトログラムをBigVGANボコーダに入力して最終音声波形を生成します。これは数行のコードで可能です。例えば:
mel_tensor = torch.tensor(mel).unsqueeze(0).to(device)  # メルをテンソルに（必要なら次元合わせ）
with torch.no_grad():
    audio_tensor = vocoder(mel_tensor)  # 波形生成
audio = audio_tensor.squeeze().cpu().numpy()  # 1次元の音声波形配列に変換
上記でaudioが生成された音声データ（numpy配列）です
huggingface.co
。生成後、必要に応じて振幅を正規化したりクリッピングしたりします（通常はそのままで大丈夫ですが、場合によってはピークが大きすぎることがあります）。
メモ: BigVGANの推論は高速ですが、CPU環境では時間がかかる可能性があります。短いテスト文であれば問題ありませんが、長い文章ではCUDA GPUの使用を検討してください。
音声ファイルへの保存: 得られた音声波形データを.wavファイルとして保存します。標準的なPCM音声にするには、サンプリング周波数をVITS/BigVGANに合わせます（22kHzモデルなら22050 Hz等）
huggingface.co
。Pythonではsoundfileやscipy.io.wavfile、librosaなどで保存可能です。例:
import soundfile as sf
sf.write("output.wav", audio, samplerate=22050)
これでフォルダ内に合成音声のWAVファイルが保存されます。日本語・英語・中国語の各入力について異なるファイル名で保存し、正しく音声が再生できるか確認してください。
中間出力（メルスペクトログラム）の可視化: 最後に、中間表現であるメルスペクトログラムを画像として保存します。Matplotlib等を使ってスペクトログラムをプロットできます。以下は簡単なプロット例です。
import matplotlib.pyplot as plt
plt.figure(figsize=(10,4))
plt.imshow(mel, aspect='auto', origin='lower', 
           interpolation='nearest', cmap='viridis')
plt.colorbar(label="Amplitude (dB)")
plt.title("Mel Spectrogram")
plt.xlabel("Frame Index")
plt.ylabel("Mel Bin")
plt.tight_layout()
plt.savefig("mel_spectrogram.png")
上記により、mel_spectrogram.pngという画像ファイルにメルスペクトログラムが可視化されて保存されます。人間の音感に近い対数メル尺度で表示され、縦軸が周波数方向（メルバンド）、横軸が時間フレームを表します。音声合成の成否を視覚的に確認する手段として、有用な中間出力です。
動作確認と次ステップ
以上の手順により、多言語対応のVITSベースTTSパイプラインの初期検証が完了します。日本語・英語・中国語それぞれについて、音声波形（.wav）と対応するメルスペクトログラム画像が得られているはずです。最後に以下の点を確認しましょう。
合成音声を実際に再生し、入力テキストの内容がおおむね発話されているか（日本語・英語・中国語で適切な音声になっているか）をチェックします。
メルスペクトログラムを目視で確認し、音声らしいスペクトルパターン（フォルマントの横縞やピッチに対応する斜めの縞など）が現れているかを見ます。特に発話に失敗している場合、スペクトログラムが不自然（ランダムノイズ状、あるいは真っ黒/真っ白など）になることがあります。
もし発話品質に問題がある場合、原因切り分けとして以下を検討してください:
音素変換やXPhoneBERT統合に起因する問題かを調べるため、一度XPhoneBERTを使わず通常のVITS推論を各言語で行い比較する。例えば英語ならテキストを直接既存の英語VITSモデルに与えて音声を出力し、BERT統合版と聴き比べます。品質差が大きい場合、統合部分の調整が必要です。
XPhoneBERT統合後のモデルを追加微調整してみる。少量でも良いので対象言語の音声データでファインチューニングすることで、BERT埋め込みからメルへの変換が安定し、品質向上が見込めます。
各言語で音素記号の扱いが適切か確認する。例えば日本語の音素がモデルの訓練時と表記揺れがあれば、対応する辞書の修正や変換ルールの追加が必要です。
以上、段階的に実装と検証を行うことで、多言語対応のVITSベースTTSシステムのプロトタイプを構築できます。最終的には、XPhoneBERTの多言語表現力とVITS+BigVGANの高品質な音声合成力を組み合わせることで、各言語で自然な音声合成が可能になることが期待されます
